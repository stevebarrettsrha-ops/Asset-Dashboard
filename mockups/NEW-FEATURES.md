## 6 brand-new features (the part that was missing)

### 1. Asset 360° Profile  (`08`)
A single page per asset: photo, QR/barcode, status pills, full specification grid, a
**lifecycle timeline** (acquired → commissioned → serviced → in-service → survey due), a
**warranty countdown ring**, live **net book value**, and an "open actions" panel
(calibration due, missing documents). Today the app only has a lookup *modal* — this turns
each asset into a real record you can drill into. Tabs for Overview / Maintenance /
Documents / History / Depreciation.

### 2. Maintenance & Service Scheduler  (`09`)
Preventive-maintenance for biomedical equipment: KPIs (due this week, overdue, uptime),
an upcoming-maintenance table with type/assignee/status, a week-at-a-glance bar, work
orders, and service alerts. Hospitals are audited on PM compliance — the current app
tracks none of this.

### 3. Depreciation & Net Book Value  (`13`)
Automated schedules with selectable method (straight-line / reducing balance / units of
production), an NBV projection chart per asset, a year-by-year schedule table, and a
depreciation-by-asset-class summary. Makes the Fiscal Year Report numbers defensible for
GOJ / IFRS reporting.

### 4. Analytics & Insights  (`04`)
Portfolio intelligence: value trend over 6 years, asset **age profile** (how much kit is
past useful life), value by department, condition mix, plus plain-English "insight" cards.
Turns raw data into decisions about what to replace and where the money sits.

### 5. Audit / Scan Mode  (`12`)
A phone-first physical-verification flow: scan an asset's QR on a walk-around, confirm
"present" or flag "missing", with a live progress bar per location and a running scan log.
This is a stock-take for fixed assets — exactly what's needed before a Board of Survey.

### 6. Notifications Center  (`21`)
One feed for warranty expiry, maintenance due, survey decisions, and import results, with
type filters, unread state, an alert summary, and **in-app toasts that replace the current
`alert()` pop-ups**.

## Suggested build order
1. **Asset 360° Profile** — highest value, and it anchors Maintenance / Depreciation / Documents.
2. **Notifications + toasts** — small, removes the dated `alert()` pattern app-wide.
3. **Maintenance** then **Depreciation** — both hang off the asset record.
4. **Analytics** and **Audit/Scan Mode** — once the data model supports them.

Nothing here is wired into the live app yet — these are for your review before I start coding.
